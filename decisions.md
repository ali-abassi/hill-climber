## 2026-10-02 — Challenge the evaluator before trusting a perfect score

Ali challenged the one-round self-climb and asked for much stronger skepticism. A perfect completion score was evidence for a narrow panel, not broad excellence. Run independent adversarial audits before scaling, preserve reproduced failures, and use a broader frozen execution/evidence panel with known-good controls and a reject-everything negative. The untouched release scores 13/49; the negative scores 0/49 and fails validity. Two independent authors supply 50 fresh private cases outside the repository, never graded manually.

Use five competing GPT-6.1 Sol high candidates per round, up to four rounds, no automatic perfect-score target, two plateau rounds, explicit candidate/evaluator/wall/token/failure bounds and no automatic application. The trusted outer controller remains the delivered baseline. Keep each candidate focused on a root cause, review the selected source, accept only strict one-time private promotion, and separate improvements from remaining limits. These are correctness cases, not model-quality, speed or OS-containment benchmarks. One deterministic repeat is not evidence about stochastic variance. Record actual rounds, stop reason and usage rather than claiming deeper search because a larger maximum was configured.

Update the reusable skill so future agents must challenge saturation, disclose uncovered dimensions and distinguish withheld private cases from filesystem security. More iterations alone are not proof. Preserve prior project history and existing user documents; all release checks must bind to the canonical checkout.
