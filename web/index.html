      01
      Define the outcome.
      Say who benefits and what improves. Include the important constraints and examples in a task brief. Let candidates explore the mechanism.
      02
      Build a trustworthy measure.
      Higher scores are better. Put every non-negotiable condition in a boolean gate. Leave scoring code fixed throughout the experiment.
      Protect these conditions
        03
        Give it room, and boundaries.
        Choose the smallest set of files that can solve the task. Keep evaluators outside those paths. Reserve genuinely unseen holdout cases outside the repository.
        04
        Start small. Learn from the misses.
        Begin with three candidates, one round, and --no-apply. Candidate and round counts bound the search; wall and token thresholds can be overshot by in-flight work.
        05
        Accept the evidence.
        A development gain is a proposal. The private holdout must promote it. Inspect the receipt and patch before applying; a retained baseline is a valid result.
        If interrupted, use the exact resume command. Never replay an interrupted holdout or reconstruct it by hand.
        Evaluator contract
        One JSON object.
        No self-grading.
        Your trusted evaluator reads the candidate files and prints:
        {
  "score": 0.85,
  "gates": {
    "required_checks": true
  },
  "feedback": [
    "Describe the remaining gap"
  ]
}
        Use a finite number for score and booleans for every gate. Send diagnostics to stderr.
        Subjective work?
        Use a versioned rubric, calibrated against human examples, and repeated clean-context judgments. A single model opinion is weak evidence.
        Know the boundary.
        Hill Climber improves files in Git. Evaluators run with your local user authority; it is not an OS sandbox. Image creation or external publishing needs separate tools and authorization.
